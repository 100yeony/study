# Azure 글로벌 인프라 용어와 개념
지리(Geography) > 지역 쌍(Region Pair) > 지역(Region) > 영역(Zone) > 데이터센터

## 데이터 센터
- 독립적인 전원 및 냉각장치, 네트워크를 갖춘 별도의 시설
- 한국 중부와 남부에 위치한 데이터 센터는 마이크로소프트가 LG U+, KT의 데이터센터를 임차해 사용 중이다. 
- 부산에 새로운 데이터 센터를 구축했다.

## 영역(Zone)
- 하나 이상의 데이터 센터를 가진 지역 내의 물리적 별도 위치를 가용성 영역(Availability Zone)이라고 함.
- 데이터 센터의 오류나 손상에 대비해 서비스의 논리적 격리와 중복성, 내결함성을 제공
- 한 지역에는 3개 이상의 가용성 영역이 있을 수 있고 각 영역 간의 대기 시간은 2ms이하를 보장
- 고가용성 및 탄력적인 서비스로 복원력과 유연성 제공, 지역 재해로부터 비즈니스 연속성 및 재해복구를 제공

## 지역(Region)
- 최상의 성능과 보안을 제공하기 위해 고속 네트워크로 연결된 데이터 센터 집합 
- 일정한 대기 시간(< 2ms)을 정의하는 경계
- 한국은 현재 중부와 남부 2개 지역을 제공

## 지역 쌍(Region Pair)
- 일반적으로 동일한 지리적 위치 내에 있는 2개의 지역을 말함
- 예외도 있음.
- 한국은 2017년에 오픈한 중부 지역을 시작으로 이후 추가된 남붑 지역과 지역 쌍을 이루며 리전 간 재해복구 옵션 제공.

## 지리(Geography)
- 2개 이상의 지역을 포함하며 데이터와 애플리케이션을 동일한 지리적 위치에 유지해야 하는 데이터 유지 및 규정 준수 경계를 말함
- 전용 고속 네트워크 인프라를 갖추며 지역에서 발생하는 장애에 내결함성을 제공
- 주로 나라별로 구분되지만, 더 큰 범주의 지리적 위치도 포함(아시아 태평양, 아프리카 등)


# Azure 리소스 관리 체계
- Azure는 효과적인 리소스 관리 체계를 제공한다.
    - Azure Active Directory, 테넌트 -> 관리 그룹 -> 구독 -> 리소스 그룹 -> 리소스 
    - 회사 -> 한국 본사 -> 서울 지점/부산지점 ->  운영부/개발부 -> 책상/컴퓨터/의자

- Active Directory를 통해 사용자를 관리하고, 관리 그룹을 통해서 구독을 액세스하고, 정책 및 권한을 효율적으로 관리한다.

## 1. Azure Active Directory(Azure AD)
- 회사나 조직에서 구성원들의 계정 정보(id, pass)와 컴퓨터 정보, 각 사용자 권한, 정책 정보 등을 저장하는 일종의 데이터베이스
- 다른 Azure AD와는 완전히 독립적이며 Azure AD 조직 간의 부모-자식 관계는 없다.
- Azure 상의 Active Directory로서 클라우드 기반 id 및 액세스 관리 서비스 
- 공간을 사용하는 사용자/그룹 등을 대표하는 용어. Azure AD 사용자와 그룹 같은 보안 주체를 제공하는 디렉터리 전용 인스턴스 
- Azure AD를 통해 구성원들에게 권한을 할당하여 테넌트를 생성할 수 있다. 
- 팀의 구성원이 로그인(인증)하고 권한에 따라(권한부여) 리소스를 액세스하게 해주는 ID 및 액세스 관리 서비스
- Azure AD Connect 기능을 통해 기존 Azure AD끼리 연결할 수도 있다. 

## 2. 테넌트(tenant)
- 쉽게 말해 한 회사나 조직. 단일 조직
- Azure AD에서 테넌트를 생성하면 *.onmicrosoft.com 도메인이 기본값으로 설정됨
- 이 테넌트에서 Azure AD가 사용자를 추가하고 권한을 할당할 수 있다.
- Organization IT 부서의 제어 하에 있는 ID 보안 경계. 보안 경계 내에서 개체 관리 및 테넌트 전체 설정 구성은 IT 관리자가 제어함.
- Azure 계정을 만들고 로그인하면 자동으로 만들어지는 Azure AD 테넌트는 기본 디렉터리가 되며 제거할 수 없다.


## 3. 관리 그룹(Management Group)
- 하나 이상의 구독이 존재할 때 각 구독마다 정책, 권한 등을 효율적으로 관리하기 어려움
- Azure 관리 그룹은 Azure 구독을 그룹화하여 조직에 많은 구독이 있더라도 해당 구독에 대한 액세스, 정책 및 규정 준수를 효과적으로 관리할 수 있도록 함

## 4. 구독(Subscription)
- 모든 리소스를 아우르는 집합
- 제품이나 서비스를 이용하거나 기술 지원을 받을 때 월 단위로 비용을 지불하는 방식
- 모든 리소스는 하나의 구독에만 연결되며 리소스 그룹들의 상위 카테고리
- 한국 지사에 사업부 별 서울 지점, 부산 지점이 있는 것 처럼 부서나 프로젝트에 따라 다른 구독 및 계획을 가질 수 있음
- 구독을 사용하면 리소스 사용량을 확인하고 청구 및 지불 방식을 제어할 수 있음
- 구독에 대한 권한 할당은 RBAC 기반으로 함

## 5. 리소스 그룹(Resource Group)
- 리소스를 하나의 그룹으로 묶어 관리하기 위한 논리적 컨테이너
- 각 리소스는 하나의 리소스 그룹에만 있을 수 있다. 
- 리소스와 리소스 그룹 이름은 변경할 수 없다.
- 동일한 구독 내에서 리소스 그룹 이름은 고유해야 한다.
- 리소스 그룹과 리소스의 위치가 다를 수 있다.
- 리소스를 다른 리소스 그룹으로 이동할 수 있다.
- 리소스 그룹의 위치는 리소스의 메타 데이터가 저장되는 위치이다. 데이터 존재 위치에 대한 규정 준수 문제가 있다면 위치가 중요함.

## 6. 리소스(Resource)
- 가상머신, 가상 네트워크 및 스토리지 계정 등 Azure IaaS, PaaS 서비스


# 역할 기반 액세스(RBAC; Role Based Access Control)
- 조직 구성원이 역할에 따라 클라우드 리소스를 액세스 하는 기능
- 구독 전체 또는 리소스 그룹, 리소스 단위로 액세스를 제어할 수 있음
- 모든 리소스 유형을 관리할 수 있는 역할은 소유자, 기여자, 독자
    - 소유자(Owner) : 할당된 사용 권한 제어 범위 내에서 모든 리소스를 관리할 수 있고, 다른 사용자 계정에 액세스 권한 할당 가능
    - 기여자(Contributor): 할당된 사용 권한 제어 범위 내에서 모든 리소스를 관리할 수 있지만 다른 계정에 액세스 권한 할당은 불가
    - 독자(Reader): 할당된 권한 범위 내에서 모든 리소스 정보만 확인 가능, 변경 불가



* tenant 그룹은 VNET 에 허용되지 않은 리소스 유형 정책이 적용되며 VNET 생성이 불가함
* VM을 만들기 위해서는 VNET을 먼저 생성해야 함.
* 구독은 하나의 관리 그룹에만 속할 수 있음.
